# Proposal

## Why

The default tolerance is `rtolx = rtoly = 2e-3`, applied per axis when no
coefficient of that axis is given. The x part is a poor default: a
tolerance relative to the x range grows with the length of the record,
not with how fast the signal changes. For 15 days of data it allows
43 minutes of time shift; for a year, 17.5 hours, more than half a daily
cycle. A caller who gives only a y tolerance (the most common case, and
what agents using the MCP server usually do) silently gets that time
slack and can see a real timing error pass.

It is also not what the reference implementations do: LBNL Funnel
defaults all six coefficients to `0`, its README examples use an
absolute `0.002`, and BuildingsPy uses `tol = 1e-3` as an absolute x/y
and local-relative y tolerance. None of them has a range-relative time
tolerance by default.

The owner has decided: **no tolerance in x unless the caller gives
one; the y default stays `rtoly = 2e-3`.**

## What Changes

- **Default change (all APIs: Rust, Python, TypeScript/WASM, CLI, MCP
  server).** The x-axis default becomes all zero (`atolx = ltolx =
  rtolx = 0`). The y-axis default stays `rtoly = 2e-3` with `atoly =
  ltoly = 0`. The per-axis resolution rule itself is unchanged: an axis
  with no coefficient given gets its default; an axis with at least one
  coefficient given uses zero for the others; an explicit zero counts as
  given.
- Consequences callers will notice:
  - `compare` without options, `Options()` / `{}` and a CLI run without
    tolerance flags now use `rtoly = 2e-3` only;
  - giving only a y tolerance (e.g. `atoly = 0.05`) no longer adds
    `rtolx = 2e-3`;
  - the reported defaults (`Options::default()` / `Tolerances::DEFAULT`,
    `default_options()`, `defaultOptions()`) and the echoed resolved
    tolerances (violation summary, MCP results) show `rtolx = 0`;
  - a test curve that is slightly shifted or delayed in time now fails
    at steep edges unless an x tolerance is given. With zero x tolerance
    the x half-width is the existing `1e-10` floor, so in practice each
    test point is checked only against the y band around the reference
    at the same x.
- This is a behaviour change of a published beta API on the 1.0.0
  line, made deliberately while still in beta. It is a change of
  default values only: no signature, type or status code changes, and
  fully explicit tolerances give exactly the same results as before.
  Callers who want the previous behaviour pass `rtolx = 2e-3`
  explicitly (or, better, an absolute `atolx` in time units).
- Documentation in every layer (rustdoc, CLI help, Python docstrings
  and stub, TSDoc, READMEs, MCP tool descriptions and server
  instructions) states the new default and what zero x tolerance means.
- **MCP server**: a failed row for which no x coefficient was given gets
  one short note suggesting an x tolerance if the signals may be shifted
  in time.
- **Housekeeping**: the two over-long requirements of the `mcp-plots`
  main spec ("Output path safety", "Existing files are kept unless
  overwrite is requested") are split so that `openspec validate --all
  --strict` passes once this change is archived. Meaning is unchanged.

### Modified Capabilities

- `tolerance-resolution`: the x-axis default becomes all zero; every
  scenario that states the old `rtolx = 2e-3` default is updated, and the
  default requirement states what zero x tolerance means and how a
  time-shifted steep edge behaves.
- `mcp-server`: the resolved-tolerance scenario reflects the new
  default; the tool description must state that there is no time
  tolerance unless one is given; new requirement for the hint on failed
  rows without an x tolerance.
- `mcp-plots`: two over-long requirements split into shorter ones
  without changing their meaning (no behaviour change).

`violation-summary`, `cancellation`, `wasm-demo-site` and
`signal-downsampling` were checked: their requirements and scenarios use
explicit tolerances or do not depend on the default, so they are not
modified.

## Impact

- Code: `crates/simtest-funnel-core` (`Tolerances::DEFAULT`, docs),
  `simtest-funnel-cli` (help text), `simtest-funnel-python` and
  `python/simtest/funnel` (docstrings, stub), `simtest-funnel-wasm` /
  `packages/sdk` (TSDoc; `defaultOptions()` follows the core),
  `python/simtest-funnel-mcp` (descriptions, instructions, hint);
  READMEs. The web demo uses explicit tolerances and is unaffected.
- Tests: tests that asserted the old default or relied on its implicit
  time slack are updated; cross-language pinned corpus values keep their
  values by passing the corpus case's tolerances explicitly.
- Users: comparisons that passed only thanks to the implicit time slack
  will fail after upgrading. Pytest snippets generated by the MCP server
  record the tolerances as given, so an older snippet that gave no x
  coefficient asserts with the new default. The changelog (generated
  from the commit) must describe the default change.
